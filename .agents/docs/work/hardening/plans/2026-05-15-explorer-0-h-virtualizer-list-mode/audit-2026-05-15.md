# Explorer 0-H Audit Addendum

## Trigger

After the initial 0-H completion, the user asked whether the work included adding `ViewNodeList` / `list` to the view-mode menu because they had tried to copy the plugin manually into `plugin-dev`. That exposed one UX gap. The user then asked for a full pass over the plan and sibling spec to find anything else that was real but skipped.

## Real Gaps Found And Fixed

1. **View-mode menu did not expose `list`.**
   - The executable plan focused on `panelExplorer.svelte` wiring and did not explicitly list `overlayViewMenu.svelte`.
   - The mode was present in the view-mode enum and panel branch, but users could not select it from the view menu.
   - Fixed in commit `dad8198`:
     `fix(0-h): expose list mode in view menu`.
   - Coverage: `test/component/overlayViewMenu.test.ts` verifies a `List` option is offered after 0-H list mode is wired.

2. **Plugins and snippets had no list-mode activation body.**
   - Spec shard `07-risks-and-open-items.md` R8 called out that state providers that previously had no activate body needed a trivial body for 0-H.
   - `panelExplorer.svelte` list activation dispatches to `provider.handleNodeSecondaryAction(node, selectedNodes)` when present, then falls back to `provider.handleNodeClick(node)`.
   - Files, content, tags, and props already had meaningful secondary/click behavior. Plugins and snippets had no-op clicks and no secondary action, so Enter/double-click in list mode did nothing.
   - Fixed in commit `bc199c7`:
     `fix(0-h): activate plugin and snippet rows`.
   - Coverage:
     `test/unit/components/explorerPlugins.test.ts` and `test/unit/components/explorerSnippets.test.ts` verify secondary activation toggles enabled state and refreshes the corresponding index.

## Audit Notes That Are Not New Product Fixes

- **TanStack measurement drift:** spec shard `03-api-contract.md` says `measureElement` is enabled, while the executable plan and implementation use the constant 32 px row-height pattern from `viewTree.svelte`. Treat this as a spec/plan drift and follow-up candidate, not a skipped executable plan step.
- **Provider `capabilities.canReorder`:** spec shard `04-panelexplorer-wiring.md` mentions `provider.capabilities?.canReorder`, but the current `ExplorerProvider` contract has no `capabilities` field. The implementation conservatively wires panel list mode with `canReorder={false}`.
- **DOM snapshots:** Task 0 / self-review wording mentions DOM snapshots for queue and active filters. The implementation used focused DOM assertion coverage rather than literal snapshot files.
- **Perf thresholds:** the original completion stopped at local `perfProbeDom` coverage. A follow-up Obsidian CLI run in `plugin-dev` proved the live global `window.__vaultmanPerfProbe` is callable and emits per-scenario wall-clock deltas. Jank-frame and heap metrics remain unavailable because the current `PerfProbeSnapshot` API does not include them. The live snapshot is documented in `perf-baseline.md`.
- **Future integration risk:** `ViewNodeList` action buttons do not stop row propagation today. Current panel list mode does not wire `onAction`, and the existing widget consumers do not wire `onSelect`, so this is not a live 0-H bug. If a future panel list mode wires row actions and selection together, add a stop-propagation test first.
- **Disabled-row DnD:** the spec mentions disabled rows not being draggable, but the executable plan asked to preserve the old list DnD behavior bit-for-bit.
  Current `draggable` gating remains based on `canReorder && onReorder`.

Actionable risks found:

1. **ARIA row ids are derived directly from semantic row ids.**
   `ViewNodeList.svelte` sets `aria-activedescendant` to `vm-listrow-${activeFocusedId}` and each row id to `vm-listrow-{row.id}`.
   File-provider row ids are file paths (`logicsFiles.ts` uses `id: file.path`), so paths containing spaces produce invalid or ambiguous ARIA idrefs. Fix with a stable DOM id encoder/sanitizer while preserving semantic `row.id` for callbacks and virtualization keys. Add a regression test with a path such as `Projects/My Note.md`.

2. **Initial listbox ArrowDown can skip the first row when no row is focused.**
   `currentFocusedIndex()` falls back to `0`; `ArrowDown` then moves to `idx + 1`, so keyboard users tabbing into a list with no `focusedId` can land on the second item. Fix by treating "no current focus" as `-1` for ArrowDown and as `rowInputs.length` for ArrowUp, or by setting initial focus explicitly on listbox focus. Add tests for ArrowDown/ArrowUp with no external `focusedId`.

Non-blocking drifts confirmed:

- The implementation still uses constant `estimateSize: () => 32` with `observeElementRect`, not per-row `measureElement`. This remains the known spec/plan drift recorded above.
- Literal DOM snapshot files for queue and active filters still do not exist;
  focused DOM assertions and stress tests are present instead.
- The live perf record has post-audit Obsidian wall-clock timings but no pre-migration live baseline and no jank/heap metrics because the current probe shape does not emit them.
