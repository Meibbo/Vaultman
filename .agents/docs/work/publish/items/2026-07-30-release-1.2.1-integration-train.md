# Release 1.2.1 Accepted-Issue Integration Train

## Purpose

This is the local-only coordination ledger for assembling the cumulative
`1.2.1` patch from independently based agent branches. Product integration is
serialized by the coordinator in `codex/integrate-1.2.1`; agents continue to
implement and verify issues in their own worktrees.

The integration branch starts at the current `origin/main`. It receives only
accepted product commits through `git cherry-pick -x`. It must never receive
`.agents/`, `AGENTS.md`, `CLAUDE.md`, agent caches, unrelated documentation,
or generated build artifacts.

## Required Agent Handoff

When an agent completes one or more issues, send the following through Agent
Room to the owner of `task_064`:

```text
INTEGRATION HANDOFF 1.2.1
Issues: U121-...
Source branch:
Worktree:
Merge-base with origin/main:
Ordered code-only SHAs:
Dependencies / required ordering:
Overlapping files or semantic contracts:
Focused verification:
Full gates:
HITL status:
Explicitly excluded commits/files:
GitHub issue state:
```

Rules:

1. Do not merge, rebase, push, tag, or modify the integration worktree.
2. Keep product and `.agents/` documentation in separate commits.
3. Report exact SHAs, not only a branch name or a range inferred from `HEAD`.
4. If a branch includes earlier or unrelated commits, list only the issue's
   code-only commits in dependency order.
5. Declare overlaps even when Git would merge them textually; semantic
   conflicts matter.
6. `ready-for-human` is not accepted. The handoff must state whether HITL is
   approved, waived by the dev, or still pending.
7. The coordinator records both source SHAs and resulting integration SHAs.

Agent Room is the canonical delivery path because startup requires mailbox
reading. A direct chat reminder is useful but does not replace the structured
handoff.

## Integration Procedure

For every accepted issue:

1. Verify source branch, merge-base, clean commit contents, and exclusions.
2. Predict file/contract overlap against the current integration head.
3. Apply ordered commits using `git cherry-pick -x`.
4. Run issue-focused regression tests.
5. Record the source→integration SHA mapping.
6. After a coherent batch, run the complete repository gates and sync a smoke
   build.

Promotion procedure:

1. Fast-forward `dev` to the current `origin/main` (it was 6 behind and 0 ahead
   when the train opened).
2. Fast-forward `dev` to the verified integration head.
3. Prepare and publish `1.2.1-beta.1` only with explicit dev authorization.
4. Validate clean install, upgrade from `1.2.0`, real mobile via BRAT, and the
   combined issue smoke matrix.
5. Promote through PR `dev → main`, then release stable `1.2.1`.
